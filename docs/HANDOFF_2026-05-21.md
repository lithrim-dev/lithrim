## How to reproduce the headline contrast (single command)

```bash
cd ~/Workspace/github.com/lithrim-bench

# Generate HL7 pack
python scripts/generate_pack.py --pack hl7_adt_v1 --size 40 --seed 7 \
    --mix clean=0.3,single=0.7,multi=0.0

# Three-way comparison (under 90s total)
for label in A.tuned_only:tuned-mock B.struct_only:lithrim-validate-artifact C.worstof:worst-of; do
    suffix="${label%:*}"; backend="${label#*:}"
    if [ "$backend" = "worst-of" ]; then extra="--worst-of-semantic tuned-mock --worst-of-structural lithrim-validate-artifact"; else extra=""; fi
    python scripts/run_determinism.py --pack-path out/hl7_adt_v1.jsonl --n 1 \
        --backend "$backend" --tuned-per-member-accuracy 0.802 \
        --tuned-flag-attachment-rate 0.218 \
        --etlp-mapping-id 26 $extra \
        --out "out/hl7.$suffix.ndjson"
done

# Report
python scripts/analyze_runs.py --runs out/hl7.A.tuned_only.ndjson --pack out/hl7_adt_v1.jsonl
python scripts/analyze_runs.py --runs out/hl7.B.struct_only.ndjson --pack out/hl7_adt_v1.jsonl
python scripts/analyze_runs.py --runs out/hl7.C.worstof.ndjson --pack out/hl7_adt_v1.jsonl
```

## Open questions worth pinning

- **Verdict severity calibration on structural defects.** When the live validator emits WARN (not BLOCK) on field-presence defects, my `expected_compliance_verdict` is still hardcoded `reject` (Tier-1 STRUCTURAL). The `verdict_match_rate` metric reads low because of this, even though `defects_caught` (any non-approve) reads correctly. Two possible fixes: (a) lift expected_compliance_verdict from the recipe's `expected_structural_verdict_when_caught` (already a field on the recipe); (b) report `defects_caught` as the primary metric and `verdict_match_rate` as a strict secondary. Pick before paper §6 wording lands.
- **Flag-attachment gap interpretation.** Should the paper report two recall metrics (verdict-level vs exact-flag) or one composite? Today's measurement: 3.5× gap (0.78 vs 0.22). Strong paper material either way.
- **Per-pack v3 artifact work.** Worth doing in the same session (small surface) or splitting per pack (cleaner commits)? My recommendation: one session, two commits.

## Single biggest risk

The headline contrast (+28.6 pp gain on HL7 pack) is a function of the deployed validator's coverage (2 of 5 defect classes). A paper reviewer will ask: "if your validator caught 5 of 5 classes, what would the gain be?" The honest answer is in `docs/HEADLINE_CONTRAST_2026-05-21.md` (simulated 60 pp at ideal coverage), and the bench can demonstrate that simulation deterministically. **Make sure the paper frames the live number as "the deployed validator on the bench" and the simulated number as "the recovery ceiling at full validator coverage."** Conflating the two is the failure mode.
