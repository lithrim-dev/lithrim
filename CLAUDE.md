# Lithrim Bench

Synthetic clinical-AI benchmark generator. Backs the Lithrim research paper and the developer product. **Read `README.md` and `docs/PAPER_OUTLINE.md` before doing anything.**

## Diagnose-before-edit (inherited from lithrim-backend)

When fixing a labeling / verdict / determinism bug, post the verbatim evidence (golden row JSON, taxonomy entry, run JSON) in a fenced code block before stating the diagnosis. Tag every causal claim **CONFIRMED** / **INFERRED** / **HYPOTHESIS**. The bench exists precisely because story-shaped diagnoses have polluted the eval before; do not repeat that here.

## Core invariant: labels are true by construction

This is the entire reason this repo exists. A case is admissible **only** if:

1. Every `expected_safety_flags` code is in `packs/healthcare/taxonomy_snapshot.json` `KNOWN_TAXONOMY_CODES`.
2. The `injection_recipe` block specifies `defect_type`, `mutated_projection`, `mutated_field_or_span`, `pre_value`, `post_value`. The recipe **is** the label justification.
3. Clean negatives have `injection_recipe: null` and `expected_safety_flags: []`. They are first-class, not residue.
4. Every flag has a `production_judges`-resident owner per `tier1_owners`. Flags whose only owner is `source_message_judge` (declared but not running) must be excluded or reassigned; never silently scored.

If a case cannot meet (1)–(4), it does **not** ship. Do not append to `examples/*.jsonl` without the lint script passing.

## Stack

- Python 3.10+
- Pydantic v2 for schemas (no v1 syntax)
- Pandas for Synthea CSV loading
- No LLM dependency for v1 deterministic synthesis. The `synthesizers/transcript.py` and `synthesizers/scribe_artifact.py` are template-based on purpose, so the benchmark generator runs offline and is byte-deterministic given the same Synthea seed + injector params.

## Conventions

- Async only where it earns its keep (it doesn't, for a CLI generator). Default sync.
- `ruff check .` / `ruff format .` is the lint.
- Tests with `pytest`. Tests must be runnable without network and without the Synthea CSV (use fixtures).
- No comments unless the *why* is non-obvious. Don't write what the code already says.

## What this repo is NOT

- Not a copy of `lithrim-backend`. The backend imports nothing from here.
- Not an LLM training pipeline. It generates eval cases; scoring lives in `lithrim-backend`.
- Not a FHIR validator. That is etlp-mapper. We *consume* FHIR; we don't validate it here.
- Not a UI. CLI + JSONL until phase 4.

## The plugin registry is the Core/Pro boundary (PLUGIN-1)

`lithrim_bench/harness/plugins.py` is the unified plugin registry (Plugin Phase-1, `docs/specs/SPEC_PLUGIN_ARCHITECTURE.md`). The three former ad-hoc registries — the pack loaders (`harness/pack.py`), the grounding contract registry (`grounding.py` `_CONTRACT_EXECUTORS` + the pack-floors merge → `contract_plugins()`), and the judge provider (`judges_dspy.py` `build_judge_lm` → `plugins.resolve_provider_id`) — are declared as `PluginManifest`/`PackManifest` entries (`kind/tier/transport/implements`). **`tier` is the single Core/Pro boundary field, read at load:** `harness/pack.py` `assert_pack_licensed` gates a `tier: pro` pack — under a denying `License` (env `LITHRIM_BENCH_LICENSE`; **default permit-all** so grading is byte-identical) the pack is ABSENT (the harness import fails closed), not stubbed. **R-GUARD:** the gate sits ONLY on the ontology/taxonomy/prompts `*_path` resolvers (above the frozen-council seam) — NEVER on `pack_tiers`/`pack_tier1_owners`/`pack_lenses`/`pack_production_judges` (the council's inline-`__import__` carve-out targets; gating them re-enters the council import). The contract/provider folds are declaration-only/byte-identical (the moat — `_apply_consensus`, the `signals.py` withstands read — is untouched). The loaded-plugin set is recorded in `PipelineProvenance` (`loaded_plugins`/`active_pack`/`pack_tier`). Adding a new contract/pack + tier-tagging it is **manifest-only, zero engine edits** (the open/closed test, `tests/test_plugin_phase1.py`). `plugins.py` is stdlib+pydantic-only (no `openai`/`dspy`). **TOOL-1 (2026-06-13):** the `tool` kind is now folded in too — `plugins.tool_plugins()` (a core static tuple ⊕ a pack's `tools.json` DATA ref via `pack.load_pack_tools()`) enumerates `kind: tool` connector/capability declarations (MCP server / API connector / KB-query / terminology / builtin) into `provenance_snapshot()`, tier-gated like every kind (a `tier: pro` tool is ABSENT under deny). **MCP is the tool-transport standard** (`transport: service` for external MCP/HTTP — Hermes SNOMED, the `etlp_jute` `:3031` connector; `in_process` for SDK-MCP agent tools); the sub-kind rides the existing `implements` string (`tool.mcp_server`/`tool.api_connector`/`tool.kb_query`/`tool.terminology`/`tool.builtin`); the connector config rides `service: dict` (secrets via env, never the manifest). DECLARATION-ONLY — a tool is USED by a flag's `verification_contract` criterion; "configure any MCP/custom/API tool" = a manifest entry, zero engine edits (TOOL-1 section of `tests/test_plugin_phase1.py`). The legacy `EvalProfile.tools`/`kb_bindings` are LEGACY-INERT (no grade-time consumer); the live plane is `kind: tool` + `verification_contracts`. **Still deferred:** TOOL-2 (the 2 Pro tools — KB-over-`:8002` + Hermes/SNOMED — built to this interface, in the pack repo), the `frontend` kind (post-CHATBIND-2), Phase-2 HPACK, Phase-3 enforcement/VPC.
