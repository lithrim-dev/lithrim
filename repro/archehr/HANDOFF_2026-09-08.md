## What exists, and what was deliberately not built

Built and tested: gold-free input normalization and prompt packets (`run.py prepare`), strict
citation/coverage/duplicate integrity checks plus native `ValueGroundingTool` numeric
diagnostics with prose-safe abstention (`run.py review`, `lithrim_feedback.py`), unlabeled
council input rows, submission JSON/ZIP export, the strict XML importer (`import_xml.py`), and
the hash-pinned official scorer wrapper (`official.py`).

Specced but deliberately NOT written, per the park decision:

| File | Role | Benchmark-specific? |
|---|---|---|
| `model.py` | Call a model; capture raw output, resolved model id / fingerprint, sampling, tokens, cost, latency, and errors as first-class failure records; mark cache replays so they cannot count as independent runs | No |
| `council.py` | Feed council rows through `grade_inprocess` + `build_authored_semantic_stage`; write `council_signals.jsonl` once, keyed by `(case_id, answer_id, submission_sha256)`, replayed identically into arms C and D | No |
| `arms.py` | The A/B/C/D driver; per-arm call and token budget hard-stops; asserts C and D share an identical starting-prediction hash and council-signal hash | No |
| `report.py` | Score frozen arms through `repro.archehr.official`; emit micro-F1, micro P/R, macro-F1, coverage, abstention rate, invalid-output rate, failures, tokens/cost/latency per arm, and paired case-resample CIs recomputing micro-F1 from pooled link counts | No |

Three of those four are benchmark-agnostic. Only `import_xml.py` and `official.py` are
ArchEHR-shaped, and both already exist. A restart on any benchmark reuses the plan.

## Blockers, exactly

1. **Dataset.** Authorized 2026 Subtask 4 release and exact release string. Requires PhysioNet
   credentialing: CITI "Data or Specimens Only Research", a credentialed account (needs a
   reference), and the DUA. Not started.
2. **DUA versus hosted inference — check this first if anyone restarts.** UNVERIFIED. PhysioNet
   DUAs have historically restricted sending credentialed records to third-party APIs. If that
   binds this release, the four-arm protocol cannot run on a hosted endpoint and needs local
   inference, which changes model choice, cost and latency for the whole design. Establish this
   before spending hours on CITI, not after.
3. **XML layout.** `import_xml.py` expects `case@id`, `patient_narrative`, `clinician_question`,
   `note_excerpt_sentences/sentence@id`, `answer_sentences/sentence@id`. This shape comes from a
   2026 participant's parser, not an organizer file. It fails closed on anything unexpected and
   must be tested against the authorized release before use.
4. **Model, endpoint, data-handling approval, and an explicit spend/call limit.** All undecided.
   The same model must serve all four arms; arms differ only in feedback.
5. **Scoring access.** A local run of the pinned scorer is not a leaderboard entry. Current
   organizer/Codabench access and test-gold availability were never established.
