## 0. Why this cycle exists (one paragraph)

WS-0 proved the spine but with everything hardcoded: one contract baked into
`grounding.WS0_CONTRACTS`, the case/baseline/severity-map passed as CLI args, the
correction record stamped `ontology_version="ws0-hardcoded/0"`. WS-1 lifts all of
that into **two new planes**: (1) a **SQLite config plane** — an *Agent* with an
*eval-profile* `{judges, council_config, ontology, tools, kb_bindings, severity_map}`
that drives the run; and (2) the **ontology data model** — the single source for
flags, tiers, owners, per-role questions, and per-flag **verification_contracts**,
**domain-agnostic by construction** (clinical is just the first seeded ontology).
This is the move that makes the harness a *product*: a new domain is a new ontology
row, not a code change. The S-BS-7 `MedPresenceCheck` becomes the ontology's **first
verification_contract** (declared as data, executed by the harness). Still **offline**:
WS-1 re-drives the captured WS-0 baseline from config — zero new paid calls.

## 2. Deliverables (file-by-file)

> Paths are the **proposed shape**; confirm or adjust the module layout in plan-review.
> The *responsibilities* and the four task-pack deliverables are fixed.

1. **`lithrim_bench/harness/ontology.py`** (NEW) — the **ontology data model** (task-pack deliverable 2).
   - Typed model: `FlagDefinition` (flag, category, definition, when_to_use, when_NOT_to_use, owner_roles, tier), `JudgeQuestion` (role, ordinal, text), `VerificationContractDecl` (flag_code, question, contract_type, params, version).
   - The **single source** for flags / tiers / owners / questions / contracts; query API keyed by flag code and by role.
   - **Domain-agnostic:** clinical is a *seeded instance*, not baked into the model. Carries a stable `ontology_version`.

2. **`data/ontology/clinical_v1.json`** (NEW, **tracked/committed**) + **`scripts/seed_ontology.py`** (NEW) — the seed (task-pack deliverable 2 + 4).
   - `seed_ontology.py` reads the §1 seed sources (`SAFETY_FLAG_DEFINITIONS`, `TIER_1_NEVER_EVENTS`/`TIER_2_HIGH_RISK`/`TIER_3_MEDIUM`, `_TIER1_OWNERS`, `council_roles/*.txt`) and emits `clinical_v1.json` — a **human-reviewable, byte-deterministic** ontology seed (per CLAUDE.md determinism ethos). The **med presence-check is the first verification_contract** in the seed, with its extraction strategy as **explicit params** (`med_source="patient_profile.active_medications"`, `token_min_len=4`, `noise_tokens=[...]`) — closes WS-0 critique **Q4.3** (no buried heuristic).
   - The `severity → verdict` mapping (WS-0 `_rescore`: HIGH/MEDIUM→BLOCK, LOW→WARN) is recorded **as ontology/config data** — closes critique **Q4.2** (ratify the thresholds as data, not a magic constant).

3. **`lithrim_bench/harness/config.py`** (NEW) — the **SQLite config plane** (task-pack deliverable 1).
   - `Agent` + `EvalProfile {judges, council_config, ontology_ref, tools, kb_bindings, severity_map}`, persisted in a **config SQLite** (separate DB from the WS-0 *results* DB `out/ws0/ws0.sqlite`).
   - `council_config` **stores** the compose-over-live-v2 disposition (ratifies **S-BS-6**) — **stored only**, NOT injected into `PipelineRequest` (that is WS-2).
   - Load API: `load_agent(name) -> Agent`; the runner reads the profile instead of CLI args.

4. **`lithrim_bench/harness/collections.py`** (NEW) — 4 slim-path **doc-shim** collections (task-pack deliverable 3, **S-BS-4 = document shim**).
   - `conversation_item`, `conversation_session`, `call_kpi`, `compliance_report` — each a doc-shim table (single JSON column + indexed keys), mirroring the Mongo collections so a later swap-back is clean. **Record the doc-shim-vs-relational rationale** in a module docstring (acceptance A3).

5. **Rewire `lithrim_bench/harness/grounding.py`** — contracts sourced from the ontology.
   - `WS0_CONTRACTS` hardcoded list → contracts **resolved from the ontology** by `flag_code`. `MedPresenceCheck` stays as the **executor** for `contract_type="presence_check"`, but its params (med_source, token_min_len, noise_tokens) come from the `VerificationContractDecl`, not module constants. `_rescore` reads the ontology severity_map.

6. **Rewire `lithrim_bench/harness/correction.py`** — `ONTOLOGY_VERSION = "ws0-hardcoded/0"` → the real `ontology.ontology_version`. Record the **owner_roles** of the corrected flag in the record (the data that later makes calibration role-aware — enables critique **Q4.1**, which is *fixed in WS-4*; WS-1 only records the owners).

7. **Rewire the runner** (`scripts/run_ws0.py` → driven from config, or a thin `scripts/run_eval.py`) — read the `Agent` eval-profile + ontology from SQLite; no hardcoded `--case/--source/--baseline/contracts`. Keep `--replay` default + `--live` opt-in (still unexercised).

8. **`lithrim_bench/picklist.py`** — **S-BS-9 normalization**: normalize `expected_compliance_verdict` to a single shape (or read a documented shape contract); record the chosen normalization. Don't silently keep the n10-first ambiguity.

9. **`tests/test_ws1.py`** (NEW) — offline tests covering A1–A3 (config-driven run reproduces the WS-0 grounded result; ontology is the single source; doc-shim rationale present). Reuse `tests/fixtures/ws0/`.
