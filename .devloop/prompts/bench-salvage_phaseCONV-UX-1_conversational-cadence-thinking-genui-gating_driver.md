## 0. Why this cycle exists — the LIVE evidence (diagnose-before-edit)

The user's verdict on the conversational surface: *"feels very laggy → UX is bad,
things just appear abruptly… Thinking Stages (these models do the reasoning) UX
needs to clearly reflect that. GenUI components should be rendered smartly,
contextually — right now it just starts throwing these."*

A live drive of `:5180` (workspace `demo-clinical`, message **"Create a risk judge
that flags unsupported clinical claims in the agent's answer."**) reproduced all of
it, and surfaced a blocking correctness bug underneath. Verbatim observed state:

```
You: Create a risk judge that flags unsupported clinical claims in the agent's answer.

Lithrim: [static "Thinking…" for ~2s, no animation]
  → (whole paragraph pops in at once) "I'll start by loading the tools I need and
     reading the current agent… The default ws0_default isn't in this config DB
     (it's a demo-clinical workspace). Let me find the actual agent."
  → (a 2nd block pops in) "…show_case resolved ws0_default fine. Let me run a $0
     replay eval (defaults to ws0_default)… The configured ws0_default isn't present
     in this demo-clinical config DB, so I can't read its roster by guessing. Let me
     try the most likely clinical agent names…"
  → GenUI **Audit trail** card renders (Config changes: author·eval-1, author·snomed-demo,
     edit·ontology·snomed-demo ×2; + a "Run provenance" pipeline_run_id loader)
  → RED error: "Could not load the case: GET /v1/case?agent=ws0_default → 404:
     Agent 'ws0_default' not found in config DB (…/demo-clinical/config.sqlite)"
  → "↗ Opened the Config panel" — right pane switches to Config editor, which ALSO
     errors: "Could not read ontology — GET /v1/ontology?agent=ws0_default → 404"
  → the judge is NEVER created.
```

Tagged causal claims:

- **CONFIRMED (live):** the felt cadence is "dead air → whole block pops in → whole
  block pops in → card pops in." Confirmed by reading `apps/bff/agent/loop.py:257-262`:
  `client.receive_response()` yields **complete `AssistantMessage` objects**, and the
  loop emits each whole `block.text` as ONE `assistant_delta`. So the SSE plumbing IS
  streaming, but the granularity is a **content block (a full paragraph), not a token**
  — that is the entire "abruptness." The wire is fine; the granularity + the absence of
  any inter-block progress affordance is the problem.
- **CONFIRMED (live):** the only pending affordance is a static `"Thinking…"` string
  (architecture map: `panes.jsx:419`, shown only while the last message is empty).
  Meanwhile `tool_call` events ARE emitted on the wire (`loop.py:264`) and the shell
  **drops them** — the data needed for "thinking stages" already streams; the UI ignores it.
- **CONFIRMED (live):** GenUI fired off-context — a "create a judge" request rendered an
  **Audit-trail** card (incidental `review_runs`/`get_agent` reads during the agent's
  orientation) and rendered it *next to a 404*. Confirmed by the architecture map: every
  tool handler unconditionally `ctx.emit(part)`; `loop.py:268-269` drains them; the shell
  renders every part with no gating/dedup/intent.
- **INFERRED (needs executor confirmation in plan-review):** the root of the 404 cascade
  is `ToolContext.default_agent == "ws0_default"` hardcoded/neutral, NOT resolved from
  the **active workspace** (`demo-clinical`, whose agents are `eval-1` / `snomed-demo`).
  Every tool keyed on `ctx.default_agent` (`get_agent`, `show_case`, `run_eval`, the
  chatbind ontology read) 404s in any non-default workspace. **Confirm the exact
  default_agent construction + the workspace's agent list, verbatim, in plan-review
  before editing.**

UX tuning on a 404-cascading surface is pointless, so **W0 (the default-agent fix) is the
precondition** — it is a correctness fix, included here because it dominates the felt
experience. If the executor finds W0 is larger than a focused fix, halt and surface it
(it may split to its own micro-cycle).

## 2. Deliverables (work-items; file paths are starting points — confirm on read)

### W0 — Default agent resolves from the active workspace (BLOCKING precondition)
- Resolve the conversational `ToolContext.default_agent` from the **active workspace's**
  declared default agent (or its first/only agent) instead of a constant `"ws0_default"`.
  A fresh chat in `demo-clinical` must target `eval-1`/`snomed-demo`; a fresh chat in the
  neutral `default` workspace must still target `ws0_default` (back-compat).
- Files: the chat endpoint / `ToolContext` builder in `apps/bff/app.py` + `workspace.py`.
- **Confirm the current construction verbatim in plan-review before editing.** Do not
  guess the resolution; read it.

### W1 — Thinking / working stages (surface what already streams)
- **Shell:** render `tool_call` events as a live, ordered **activity affordance** — a step
  line / chip per tool with a human label ("Reading agent…", "Authoring judge…",
  "Running $0 replay…") and a running→done state. The events already arrive (`loop.py:264`);
  `panes.jsx onEvent` must stop dropping them.
- **Shell:** replace the static `"Thinking…"` with a non-static working indicator that
  reflects the current activity (animated dots / shimmer; shows the latest tool label when
  one is in flight, a generic "Thinking…" otherwise). Must appear during the FULL in-flight
  window, not only when the message text is empty.
- **BFF (optional, only if cheap):** add a `tool_status` running/done lifecycle event so a
  long tool (replay `run_eval`) shows a live spinner rather than a frozen gap. If the SDK's
  message ordering makes a clean "running" marker awkward, ship the shell-side
  tool_call→done timeline alone and note it.
- **BFF (verify-then-maybe):** if `claude_agent_sdk` exposes a `ThinkingBlock` (or partial
  thinking) on THIS query path, emit `{"event":"thinking","text":…}` and render it as a
  collapsible muted "reasoning" section. **If the SDK does not surface thinking on this
  path, DO NOT fake it** — document the finding and skip. (Honesty bound.)

### W2 — Cadence / abruptness (soften the block-pop; spike token streaming honestly)
- **Spike (time-boxed, ≤ the executor's judgment):** determine whether the Agent SDK
  supports finer-than-block streaming on the `client.query(...)` / `receive_response()`
  path (e.g. `include_partial_messages`, partial `StreamEvent`/`TextBlock` deltas via
  `receive_messages()`). If feasible with a small, safe change, emit finer `assistant_delta`s
  so text accretes smoothly. **Document the verdict in the REPORT either way.**
- **Guaranteed stop-gap (ships regardless of the spike):** in the shell, reveal each
  arriving block with a brief settle/fade (no hard "snap"), and keep the W1 working
  indicator visible between blocks so dead air reads as progress, not a freeze.
- **Honesty bound:** if token streaming is not available on this path, the shipped result
  is "honest cadence" (staged progress + soft block reveal), NOT a claimed token stream.
  Do not narrate a capability that isn't there.

### W3 — GenUI contextualization / gating (stop "throwing these")
- **Error suppression:** a card MUST NOT render when its underlying tool call failed. Audit
  every `*_handler` in `tools.py`: `ctx.emit(part)` only on success; on error return the
  `_error(...)` text and emit no part. (The live Audit-trail-card-next-to-404 must not recur.)
- **Dedup:** suppress duplicate card *types* within a single turn (e.g. two `get_agent`
  reads → one `agent_editor` card). Shell-side `seen`-set in the `onEvent` handler, or
  BFF-side dedup before draining `ctx.parts` — executor picks the cleaner locus.
- **Intent gating:** add a `show_intent` tag to parts (`"auto"` | `"ondemand"`). The PRIMARY
  result of the user's request renders `auto` (a "create a judge" turn → the judge editor).
  Incidental orientation reads (`review_runs`, `get_agent` the agent calls to find its
  footing) render `ondemand` — a compact "Show audit trail ▸" affordance, not a full card,
  unless the user actually asked to see it. Keep the default conservative: when unsure, an
  editor/verdict the user asked to create/run is `auto`; a passive read is `ondemand`.
- **Outcome check:** re-running the exact live message must yield the judge-editor card as
  the primary surface, with NO off-context Audit-trail card and NO 404.

### W4 — Tests
- Extend `tests/test_uap5c_journey.py` / `tests/test_ws5_bff.py` (hermetic, `_house_fixture`):
  - W0: a chat turn in a non-`default` workspace resolves `default_agent` to an existing
    agent (no `ws0_default` 404).
  - W1: a turn that calls a tool yields a `tool_call` event the shell can render; the
    pending indicator is present for the whole in-flight window (assert at the event/state
    layer the shell consumes).
  - W3: a failing tool emits NO part; two same-type reads dedup to one; an `ondemand` part
    carries the right tag. (Assert on the `run_chat` event stream — it is stub-driven and
    needs no network, per the existing loop test pattern.)
- Keep tests network-free and offline (CLAUDE.md: tests run without :8002/:3031/Synthea).
