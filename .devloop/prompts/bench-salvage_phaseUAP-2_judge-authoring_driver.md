### The prompt↔ontology bridge (the core architectural piece — OQ-1)

1. **`lithrim_bench/runtime/council/judges_dspy.py`** (+ maybe a small `judge_assignment.py`) — render the judge's `role_key_questions` from the **assigned ontology** rather than only the raw `.txt`.
   - A `render_role_questions(ontology, role)` that composes `ontology.questions_for(role)` (ordinal-ordered) + the assigned flags' lens (`when_to_use`/codes), producing the text fed to `JudgeSignature.role_key_questions`.
   - `build_trio`/`build_judge_lm` gain an optional `ontology=`/`questions=` path: when present, the judge's prompt is **rendered from the assignment**; when absent, falls back to `load_role_prompt(role)` (back-compat — A5). Keep the `.strip()` parity (S-BS-44).

### The BFF judge surface

2. **`apps/bff/app.py`** — `GET /v1/judges` + `GET/PUT /v1/judges/{role}` (REUSE the UAP-1 pattern):
   - `GET /v1/judges` → list each role + bound model + assigned lens (flags) + derived questions + attached validator refs.
   - `GET /v1/judges/{role}` → that judge's full config.
   - `PUT /v1/judges/{role}` → body = {assigned_flags[], model, validator_refs[]}; **validate** (owner↔emit: every assigned flag's `owner_roles` includes `role` AND `role` emits it — S-BS-31/42; in-snapshot; owner-consistent lens vs `LENS_BY_ROLE`) → **422** on violation; persist with the **request actor** (`_resolve_actor` + `AuditLog`) → **clobber-safe working copy** (never the committed seed). **Write-through:** the assigned flags' questions land in the ontology working copy (`questions[]`); a small judge-config row (model + assigned-lens + validator-refs) persists per §12.2.
