## 0. Why this phase (the corrected grounding-floor plan)

The runtime grounding floor is thin: **1 of 19 gradeable flags** has a `verification_contract`.
The prior plan ("generate a Jute validator for FABRICATED_HISTORY to fix the diabetes
over-fire") was **derisked and rejected on 4 axes** (see the spec §1): wrong flag (the
`diabetes_soap_clean_compliant` over-fire is HALLUCINATED_DETAIL + INCOMPLETE_DOCUMENTATION,
not FABRICATED_HISTORY), wrong direction (Jute is FLOOR/PASS→BLOCK; an over-fire needs
SUPPRESS/BLOCK→PASS), wrong tool-class (those flags are semantic, not presence-checkable),
wrong root cause (a lone miscalibrated judge + `max(severity)` rescore).

**This cycle ships the REAL, derisked fix:** a `record_presence` **suppress** executor that
grounds an artifact's documented PMH against the patient record (`patient_profile.conditions`).
The primitive already exists and is purpose-built — `InRowTool` in
`lithrim_bench/verification/tools.py` (`extract_pmh_items` + `snomed_core` match) — it is just
**not wired** into `grounding._CONTRACT_EXECUTORS`. PROVEN this session on the **real** tool:


This is the S-BS-7 suppress exhibit generalized from the transcript to the patient record —
the "only patient-record grounding flips it" finding ([[critique-pass-precision-not-floor]]),

**Terminology/Hermes (code-based grounding) is the NEXT phase (TERMINOLOGY-1), not this one** —
this cycle uses the string-match `snomed_core` (honest caveat: it works because the synthetic
bench mints note-PMH and `conditions` from identical strings; Hermes generalizes it later).

## 2. Deliverables (file-by-file)

**A. D1 — The `record_presence` suppress executor** (`lithrim_bench/harness/grounding.py`).
1. New `RecordPresence(VerificationContract)` class (mirror `KbGrounding` `:178`): `__init__(decl)`
   reads `params` (`oracle_path`, `extractor`, `match`, `artifact_decode`); `check(finding, case)`
   decodes the artifact (D2) → builds a `Claim`+`VerificationSpec` → calls `InRowTool().verify(...)`
   → maps `conforms is True` ⇒ `Verdict(disproved=True, reason=…, evidence=ungrounded-is-empty)`,
   `conforms in (False, None)` ⇒ `Verdict(disproved=False, reason=…)`. **Conservative:** never
   suppress unless ALL extracted PMH items are grounded (the existing InRowTool semantics).
2. Register `"record_presence": RecordPresence` in `_CONTRACT_EXECUTORS` (`:290`). `InRowTool` is
   pure-stdlib → it is NOT an `_HTTP_CONTRACT_TYPES` member (no http_client threading).

**B. D2 — The FHIR-DocumentReference decode** (shared read-only helper).
3. A small helper (in `grounding.py` or a tiny `harness/` util, reusing the `injectors/_soap.py`
   read logic) that takes `case["artifacts"][0]["content"]`, parses the DocumentReference JSON,
   pulls `content[0].attachment.data`, and returns the SOAP text (try base64-decode, fall back to
   plaintext). **GUARD:** any artifact that is NOT a SOAP-bearing DocumentReference (no
   `content[0].attachment.data`, e.g. the scheduling/triage conversation artifacts) → the executor
   returns `Verdict(disproved=False)` with an inconclusive reason — **never suppress by silence**
   (the `conforms=None` discipline). This was observed live: the scheduling/triage rows raise
   `KeyError 'content'` on naive access.

   ```json
     "flag_code": "FABRICATED_HISTORY",
     "params": { "oracle_path": "patient_profile.conditions",
                 "extractor": "soap_pmh_items", "match": "snomed_core",
                 "artifact_decode": "fhir_documentreference" },
     "question": "Is each documented history item grounded in the patient record?",
     "version": "record-presence/v1"
   ```

   Everything else in `clinical_v1.json` byte-identical. If the file is regenerated by
   `scripts/seed_ontology.py`, the contract must survive a re-seed (confirm the seeder carries
