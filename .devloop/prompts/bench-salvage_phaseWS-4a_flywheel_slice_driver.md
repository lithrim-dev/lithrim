## 0. Why this cycle (one paragraph)

This is the **thin** half of the original WS-4 (the rigorous locked-gate half is now **WS-4b**). It closes the data-flywheel loop end-to-end on `clinical_v1` using the judge (live `:8002`, captured/replayed) + the WS-3a structural floor that already exist — turning the ad-hoc correction stream into a first-class, versioned **correction corpus** (the RLVR/data-lake seed), a thin reusable **eval-pack**, and a **minimal calibration check**. The point is to make the flywheel tangible and let the slice *reveal* what a clean judge-capability API needs to expose — NOT to harden that API now. Everything is offline/replay; no new paid calls; `clinical_v1` stays floor-less so **S-BS-16** + **S-BS-13** remain inert.

Decide **committed example-fixture vs runtime-store** at plan-review (lean: schema + reader live in `harness/`; a committed example corpus fixture under `tests/fixtures/`; runtime appends stay gitignored under `out/`).

2. **`lithrim_bench/harness/evalpack.py`** (NEW, suggested) — **D1: thin eval-pack abstraction.**
   - Additive `{pack_id, cases: [{case, expected}], outcomes: [{grounded outcome + correction provenance}]}`. A builder that runs `run_eval.run():101` over a `PACK_FILES:20` pack (reuse `load_case:101`) and freezes a reusable artifact. Round-trippable (build → load → identical).

3. **`lithrim_bench/harness/report.py`** (extend) — **D2: minimal calibration check.**
   - A function that takes an eval-run and returns `{verdict_match_rate, ece, status: "PASS"|"WARN"}` reusing `calibration:88` + `composite:22`. **Reported PASS/WARN only — NOT a locked gate** (that's WS-4b). No threshold is "locked" or preregistered here.

4. **`tests/test_ws4a.py`** (NEW) — **D3: tests for D0–D2.**
   - Offline, replay-only (`grade_replay:40`), byte-deterministic. Covers A1–A4 below.
