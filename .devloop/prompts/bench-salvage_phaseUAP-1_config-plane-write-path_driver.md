## 2. Deliverables (file-by-file)

UAP-1 lands **R0** (audit record shape + actor model + append-only config-change log + minimal surfacing), **R1** (`/v1/agent` write-path), **R3** (draft→grade loop). Group the work into these units:

### R0 — Audit foundation (cross-cutting; the record shape + actor model land here, per §5 R0)

1. **`lithrim_bench/harness/audit.py`** *(NEW)* — the audit substrate.
   - An `AuditRecord` model (Pydantic v2 — match the stack; CLAUDE.md "no v1 syntax") with the **§2B shape**: `ts` (UTC ISO8601), `actor {type, id}`, `action`, `target {type, id}`, `why` (typed-by-action dict — for UAP-1 the `user authoring edit` type `{rationale, before, after}` is the one exercised), `before`, `after`, `run_id|null`, `case_id|null`.
   - An append-only `AuditLog` over a SQLite `config_audit` table — **INSERT-only, never UPDATE/DELETE** (immutability is the invariant; §2B). Stdlib `sqlite3`, deterministic, the same doc-shim posture as `config.py`/`collections.py`. A `record(audit_record)` writer + a `query(*, actor=None, target_type=None, target_id=None, since=None)` reader.
   - A `now_iso()` / actor helper so timestamps + actor attribution are consistent. (The `ts` must be real wall-clock — use `datetime.now(timezone.utc)` as `config.py:133` already does; this is NOT a workflow script, the `Date.now` ban does not apply.)

2. **`lithrim_bench/harness/config.py`** — wire `save_agent` to the audit log.
   - `save_agent` gains an **`actor`** handle + an optional **`audit_log`**; on every write it computes `before` (the prior `agent_to_dict` if the row exists) → `after` (the new payload) → emits an `AuditRecord {actor, action:"edit"|"author", target:{type:"agent", id:name}, why:{rationale, before, after}}`.
   - **Back-compat:** the low-level `save_agent`/`seed_config_db` default `actor` to `{type:"system", id:"seed"}` and a **no-op-if-unset** audit log, so seeding + existing tests don't churn. The **BFF write path MUST pass a real SME actor** — un-attributed *product* writes are a bug (§6), even though the low-level seed default is `system`.

### R3 — draft→grade loop (S-BS-26b)

3. **`scripts/run_eval.py`** — let a run read the agent's working-copy ontology.
   - `run(...)` gains an optional **`ontology_path: Path | None = None`**: `None` → `agent.ontology_abspath()` (the committed seed — **byte-identical to today**, back-compat); set → that path (the working-copy draft).
   - Thread it through **BOTH** committed-seed reads: `:109` (`load_ontology`) and `:142` (the live-inject `read_text`). Use one resolved `ontology_src` variable so the two reads can never diverge.

### R1 — `/v1/agent` config-plane write-path + R0 audit-on-write + R3 working-copy resolve (BFF)

4. **`apps/bff/app.py`** — the net-new routes + the audit wiring.

Never writes the committed seed `data/config/agents/*.json` (writes the config DB only, which is already non-committed product state).
   - `PUT /v1/ontology`:257 — add the **actor-attributed audit record** on the existing working-copy write (R0 across all config writes).
   - `POST /v1/run-eval`:134 — **R3**: resolve the working-copy ontology (reuse the exact "prefer working copy" logic `GET /v1/ontology`:215 already uses via `get_ontology_workdir`; factor a `_resolve_ontology_path(agent, workdir)` helper) and pass it as `run_eval.run(..., ontology_path=...)` so a PUT-ed draft actually grades. Record which ontology (committed vs draft) the run used in the run's audit context.
   - `GET /v1/audit?actor=&target_type=&target_id=&since=` → `AuditLog.query(...)` (the config-change stream, §2B stream 1).
   - `GET /v1/runs/{id}/audit` → assemble a why/when/who/what **run-provenance report** from the blob: read `PIPELINE_RUNS.get(run_id)` **synchronously** (the collection's sync `.get`; do NOT spin an event loop in the sync handler) and project the per-judge votes + reasoning + evidence + final verdict+why into the §2B report shape (§2B stream 2).
