## 0. What this cycle is (and is NOT)

**The goal (SPEC §4 Assist step / §6 G2, the KEYSTONE):** turn the conversation into *describe-the-criterion-in-English →
get-the-deterministic-contract-pre-filled*, so a physician authors a `verification_contract` **without
hand-writing JSON**. The assist uses the **already-proven retrieval-only `kb_context`** to cite the org
policy verbatim, then surfaces the `ContractBuilder` **pre-filled** with suggested `presence_check`
params. The human edits and **Saves** (the existing audited `putGroundingContract`).

**THE SPINE INVARIANT (the thing this cycle must not break):** assist sources are AUTHORING-TIME ONLY.
The suggestion is a **default in an editable field**; only the human's Save pins it; only the pinned
deterministic contract decides at grade time. The assist must NEVER auto-write the ontology and NEVER
enter `ground()`. (CONFIRMED by the scope workflow: `kb_context` is `KbRagTool.search()` — physically
separate from the grade-time `KbRagTool.verify()`; `author_contract_handler` is emit-only.)

**The smallest demonstrable cut (target = `presence_check`):** chosen because it is the always-registered
CORE suppress executor — no pack/license gate, no `:3031`/`:8002`/Hermes service dependency, pure-stdlib —
with a known 4-key param shape (`med_source`, `dosage_regex`, `token_min_len`, `noise_tokens`,
grounding.py:134-137) to suggest, and no `inject_flag_code`/`inject_severity` (suppress, not floor).
Live-demonstrable as: *"I described the criterion in plain English; the params came pre-filled with the
policy cited; I clicked Save; the floor ran at grade time — zero hand-JSON."*

**NOT this cycle (honest deferrals — see §4):** SNOMED authoring-time retrieval → **FAUTH-3b** (NO
in-product authoring path exists today: Hermes is grade-time-only via the pack's `SnomedSubsumptionGrounding`
over a machine-specific MCP; building an authoring terminology tool is net-new + carries the
ground-by-CODE-only constraint). Floor-type param suggestion, the KbPicker re-point (FAUTH-5), OpenEvidence
(FAUTH-6), and the case-10 APPROVE→BLOCK flip (FAUTH-4/NARR-FLOOR-1) are all out.

## 1. Plan-review checkpoint (non-negotiable) — risks to resolve

- **R1 — who composes `suggested_params`.** Options: (a) the AGENT composes the param VALUES from the
  prose + the cited policy and passes them to `author_contract(suggested_params=…)`; (b) a deterministic
  BFF helper returns the canonical presence_check skeleton (correct KEYS + sane defaults) and the agent
  only supplies the chart-path/flag; (c) hybrid — a deterministic helper supplies the correct KEY
  skeleton (so the agent can't hallucinate keys) and the agent fills domain VALUES informed by
  `kb_context`. **Spine note:** all three are spine-COMPLIANT (the human edits + Saves; the LLM
  suggesting authoring-time values a human reviews is allowed — only grade-time deciding is forbidden).
  RECOMMENDATION: (c) — a pure deterministic `presence_check` skeleton helper (correct keys + canonical
  defaults) the agent populates; keeps the param KEYS correct-by-construction without an LLM, while the
  prose→VALUES mapping is the agent's authoring-assist. State your choice + why.
- **R2 — the spine-guard test (the load-bearing one).** Design the NON-VACUOUS guard: driving the full
  assist sequence (`kb_context` then `author_contract` with `suggested_params`) mutates ZERO ontology and
  `ground()` over a fixture sees NO new contract; while an EXPLICIT `putGroundingContract` for the same
  flag DOES mutate + DOES make `ground()` build the contract (proving the guard catches a real write, not
  a no-op). Mirror `test_ingest_cases_bound.py` / `test_contract_builder_part.py` spy patterns.
- **R3 — the presence_check default VALUES source.** The KEYS are fixed (grounding.py:134-137). For the
  VALUES, find the canonical seeded healthcare `presence_check` (grep the repo + `../lithrim-pack-healthcare`
  for an existing presence_check contract / the S-BS-7 demo defaults: `med_source`, `dosage_regex`,
  `noise_tokens`). Clone byte-exact if a canonical seed exists; otherwise use curated sane defaults
  (`med_source` → the canonical chart path, e.g. `patient_profile.active_medications`). MUST be
  deterministic (same input → same output, no network, no LLM). Say which you used + where it came from.
- **R4 — extend `author_contract` vs a new sibling tool.** RECOMMENDATION: EXTEND `author_contract` —
  add optional `suggested_params: dict` (+ optional `question: str`) to `AUTHOR_CONTRACT_SCHEMA`
  (still NO PAID_KEY), so the conversational tool COUNT stays 20 and the A-SAFE allowlist is unchanged.
  A new tool would widen the surface for no benefit. If you add a tool anyway, justify + update every
  pinned count. Either way the handler stays EMIT-ONLY (calls no bound write op).
