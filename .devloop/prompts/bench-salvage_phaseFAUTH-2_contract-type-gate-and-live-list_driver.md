## 0. What this cycle is (and what it is NOT)

**The goal (SPEC_FLAG_AUTHORING §3 "the half that is NET-NEW" + §9 G3 / OQ-2):** enforce the spine
invariant's second half **at author time**, and make the inline builder's type list **pack-true**
instead of a hand-maintained constant.

Today the spine invariant is only HALF enforced, and at the wrong moment:

- **CONFIRMED (the gap):** `_validate_ontology` (`app.py:1697`) validates ontology shape/admissibility
  but does **NOT** check that each `verification_contract.contract_type` resolves to a registered
  executor. So a bogus / free-text / future-"openevidence_judge" `contract_type` is **fully
  persistable today** — it only blows up at **grade time** (a 500 / "no executor registered for
  contract_type X" mid-batch — the verbatim behavior described at `app.py:651-652` and `993-995`).
  The author pins a landmine; it detonates later, on someone else's run.
- **CONFIRMED (the footgun, FAUTH-1 left it as a static guard):** `ContractBuilder.CONTRACT_TYPES`
  (`ContractBuilder.jsx:35`) is a hardcoded `["presence_check", "snomed_subsumption",
  "record_presence"]` — it has to be kept in sync BY HAND with whatever the active pack actually
  registers (carried as seam **S-BS-FAUTH1-1**).

**This cycle = two moat-safe moves over the EXISTING write path + the EXISTING accessors:**

1. **The author-time registration GATE.** At the single write chokepoint `_put_grounding_contract`
   (`app.py:2375`, called by BOTH the card POST and the `add_grounding_contract` chat tool), refuse
   to persist a contract whose `contract_type` is NOT in the active pack's registered executor set
   (`grounding.suppress_executors()` ∪ `floor_executors()`). Fail-closed with a 422 + a clear message;
   the chat handler's broad `except` (`tools.py:579`) already turns that into honest guidance. This
   moves the existing grade-time RAISE (`grounding.py:599-600`) UP to author time — a prose/unknown
   type can never be pinned.
2. **The live type list.** A read-only `GET /v1/grounding-contract/types` returns the active pack's
   registered executor keys; `ContractBuilder` fetches it on mount, with the current static set as the
   offline/back-compat fallback. Retires **S-BS-FAUTH1-1**.

**This cycle is READ-ONLY against the moat.** It calls `grounding.suppress_executors()` /
`floor_executors()` (public accessors) — it does NOT edit `grounding.py`, `ground()`, the executors,
or `_apply_consensus`. No new SDK-MCP tool (the conversational surface does NOT widen; A-SAFE
allowlist + tool count UNCHANGED). No new floor. No new gradeable flag / no re-snapshot.

**NOT this cycle (the load-bearing scoping decision — see §4 + R-MOAT):** the spec §3 names the
*deeper* gate — an `oracle_kind ∈ {code,structure,value}` MARKER on each executor + a validation pass
INSIDE `suppress_executors()`/`floor_executors()` (`grounding.py:377-395`) that refuses any executor
lacking the marker. That is **split to FAUTH-2b** because (a) `grounding.py` is moat byte-frozen, and
(b) the pack executors live in the EXTERNAL `../lithrim-pack-healthcare` repo and carry no such
marker, so a fail-closed marker-gate at the accessor would **suppress the clinical floors**
(`record_presence`/`snomed_subsumption`/`dosage_grounding`) → grade regression. FAUTH-2b is a
coordinated cross-repo change (tag the pack executors FIRST, then gate). The author-time TYPE gate
achieves the enforceable half of the invariant (no prose contract can be pinned) without that hazard.
