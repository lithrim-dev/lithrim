## 0. The goal

**"Fully demonstrate Lithrim from the conversational interface."** Today the chat (the BFF Agent-SDK loop) renders gen-UI cards INLINE, but it cannot drive the **3rd pane** (`ArtifactPane`: Report / Judge council / Config / Corpus). The pane is opened only by a HUMAN click (`onOpenArtifact` on a card, e.g. `panes.jsx:251`) or the manual **Run eval** button. CHATBIND-2 gives the conversational agent a **pane-control channel** so it can — *smartly, as part of the conversation* — open the artifact pane, focus the right tab, and load that tab's data. Plus a prompt that tells the agent WHEN to do it.

This is the natural follow-on to **CHATBIND-1** (which bound the chat's tool-context to the active agent). It composes over the EXISTING plumbing — `openArtifact(t)` already does `setTab(t)+setOpen(true)` (`app.jsx:171`) and is already passed into the chat pane (`app.jsx:183`); the SSE already streams gen-UI parts (`tool_result {part:{type,state,output}}`, `loop.py:15`). The gap is (a) the agent has no way to EMIT a pane directive, and (b) for the run-bearing tabs the chat's run result isn't threaded into the pane.

**Strategic note (do not implement beyond this cycle):** this is the runtime behaviour behind the future **`frontend`/`component` plugin kind** (SPEC_PLUGIN_ARCHITECTURE, Plugin Phase-1). CHATBIND-2 builds the trigger *channel*; it does NOT build the plugin registry. All Core surface, all `$0`.
