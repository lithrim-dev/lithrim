## Re-scope note (read first) — two drifts the re-grep surfaced

This phase was **re-grepped against current code** (`../lithrim-backend@mvp-ready`,
HEAD `6720c70`) before authoring. All symbol citations CONFIRMED, but two
architectural premises in the task pack **drifted** and become plan-review
decisions:

**DRIFT 1 — the recompose BOUNDARY.** `observation_workflow.py` is not purely
observation/KPI. Its `StateGraph` (`_build_workflow:101`) is a linear pipeline of
**nine** nodes:

```
process_input_item → get_transcription_data → analyze_audio
  → run_parallel_analyses (4-way asyncio.gather fan-out) → aggregate_kpis
  → check_hipaa_compliance → evaluate_artifacts → save_compliance_results → END
        (every node has a conditional edge to a handle_error sink)
```

The first five nodes are the **OBS scope** (the 7 agents: transcription ingest +
the 6 KPI). The last three are a **compliance tail**, and
`check_hipaa_compliance:651` **delegates to `ComplianceWorkflow().process()`**
(`observation_workflow.py:686-687`) — i.e. the very compliance grade path that
**WS-6c-AGENTIC already recomposed in-process** as `runtime/pipeline/orchestrator.py`.
So the recompose boundary is: **recompose the KPI half (`process_input_item` …
`aggregate_kpis` + the 7 agents); treat the compliance tail as a documented
hand-off seam to the already-recomposed orchestrator — do NOT re-port it.** This
is the D2 "verify-and-document, don't rebuild nodes" pattern (WS-6c-AGENTIC
handoff) applied at the OBS boundary. *(Aside: the `check_hipaa_compliance` /
`evaluate_artifacts` node names that the WS-6c-AGENTIC re-grep flagged "MISSING
from `compliance_workflow.py`" live HERE, in `observation_workflow.py` — that
note is now resolved.)*

**DRIFT 2 — the dependency posture (affects A2 "default install unchanged").** The
pack's "plain async agent classes (no Mongo/Azure/LangGraph coupling)" framing is
literally true for those three (it's Gemini not Azure; LangGraph lives only in the
workflow being recomposed away) but **glosses the real couplings**: three KPI
agents are **Gemini-LLM-backed** (`intent_quality_agent.py:11`,
`sentiment_agent.py:7`, `safety_agent.py:8` import `get_gemini_service`),
`audio_analysis_agent` pulls `numpy:4` + `app.services.s3_service:87`, and **all
seven** import `app.models.call_kpi` (the KPI Pydantic models = the
`ObservationState` field-contract source) plus `app.utils.agents` / `app.services.*`.
A faithful in-process recompose therefore needs a **dependency-isolation answer**
(optional extra + lazy/guarded imports, mirroring `[council]` / `[verification]`),
not a trivial default-install port. **The pack's `ROUTINE` / "no-coupling"
hardness rationale should be reconciled** (monitor recommendation; see Hardness).
