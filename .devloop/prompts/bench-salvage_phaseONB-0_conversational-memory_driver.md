## 0. Why this phase (the de-risk #1 foundation)

The 2026-06-06 de-risk arc (`PLATFORM_THESIS_bounded_context.md` §4-5) sequences three gaps to
de-risk the platform as a governance claim: **#1 SME-authorable bounded context** → #2 governance
audit → #3 grounding floor. Gap #1's on-ramp is `SPEC_ONBOARDING_JOURNEY` (the teaching layer that
turns the proven operator loop into something a novice can learn from). **`SPEC_ONBOARDING_JOURNEY`
§2A names a single load-bearing dependency: conversational memory (S-BS-87).** Everything in that
spec — curriculum progression, contextualization to the user's domain, "where were we" — depends on
the chat loop remembering across turns. It does not today.

This cycle ships **only** that foundation: make `POST /v1/chat` memory-coherent. It is small,
spec-resolved (OQ-1), and probe-de-risked (the dry-run report confirmed the failure in code; Probe A
confirmed the teach-prompt works *once memory exists*). It unblocks Phases 1-4 of the onboarding
journey and is the literal first build of de-risk gap #1.

**The mechanism insight (monitor pre-scan):** the agent is already robust *within* a turn because it
re-reads live config (`get_agent`/`get_judge`) every message — so it never needs history to recover
*config state*. What it needs is the conversational *thread*: the user's stated domain, what it just
taught, what it just changed. A replayed transcript of prior **text** turns supplies exactly that,
while the live reads stay the source of truth. This is why text-only history is sufficient *and*
A-SAFE (no tool args, no re-execution).
