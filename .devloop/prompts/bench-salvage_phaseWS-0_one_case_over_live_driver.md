## 0. Why this cycle exists (one paragraph)

This is the **walking-skeleton spine**. We are building a domain-agnostic,
tool-grounded eval/calibration harness by **composing over the live verification
stack**, not by vendoring it (vendoring = M1, now demoted to WS-6). WS-0 proves the
full vertical on exactly **one case**: ingest → grade (live `:8002 /v1/pipeline/evaluate`)
→ persist → **harness-side grounding** → composite report + calibration report. The
grading seam was **PROVEN LIVE 2026-05-30** (HTTP 200, ~40 s; baseline saved). The
new code this cycle — persist, grounding, correction record, report — is built and
tested **entirely offline against that captured baseline**, so the cycle costs **$0**
in new paid calls. The load-bearing exhibit is **S-BS-7**: the live council emits
`MEDICATION_NOT_IN_TRANSCRIPT` as a confident false positive, and a harness-side
presence-check ("is the med in the transcript?") **disproves and suppresses it** —
the first tool-grounded verdict correction, captured as a fine-tuning-ready record.

## 2. Deliverables (file-by-file)

> Paths below are the **proposed shape**; if you have a cleaner placement inside the
> existing `lithrim_bench/runtime/` tree, propose it in plan-review. The *responsibilities*
> are fixed; the module layout is negotiable.

1. **`lithrim_bench/harness/grade.py`** (NEW) — the grading seam, compose-over-live.
   - `grade_live(case, *, env=".live_env") -> PipelineResult-dict` — builds the
     `PipelineRequest` body (inline transcript+artifact, `org_id` from `.live_env`
     **in the body**, `eval_mode=true`), POSTs `:8002 /v1/pipeline/evaluate` with
     `X-API-Key`, returns the parsed result. **This is the live path; it is NOT
     exercised for this cycle's acceptance.**
   - `grade_replay(case, baseline_path) -> PipelineResult-dict` — loads the captured
     baseline. **This is the path WS-0 acceptance runs through** (zero new paid calls).
   - One switch (`--live` / `--replay`, default `replay`) so the spine is real but
     the cycle is free.

2. **`lithrim_bench/harness/persist.py`** (NEW) — fs blob + SQLite **doc-shim** (S-BS-4 DECIDED = document shim).
   - `persist(case_id, record) -> None` — writes the full `{request, result, provenance}`
     blob to `out/ws0/<case_id>.json` (fs) **and** a row to a SQLite doc-shim
     (`_id`, `case_id`, `json` text column, `created_at`). Document shim = a single
     JSON column, **not** relational tables (so it swaps back to Mongo cleanly later).
   - Keyed by `case_id`; idempotent (re-run overwrites the same key).

3. **`lithrim_bench/harness/grounding.py`** (NEW) — harness-side, post-hoc grounding.
   - `VerificationContract` — a small abstraction: `{flag_code, question, check(finding, case) -> Verdict}`.
   - **The one WS-0 contract** (hardcoded — the SQLite ontology is WS-1): the S-BS-7
     **presence-check** for `MEDICATION_NOT_IN_TRANSCRIPT` — extract the med name from
     the finding/transcript and test substring/normalized presence in `case["transcript"]`.
     `zidovudine` present ⇒ finding **disproved** ⇒ suppress.
   - `ground(result, case) -> GroundedResult` — runs every contract that matches a
     finding's code; suppressed findings are removed from the active set and re-scored;
     **S-BS-8 null-code findings are skip-logged** (kept in the report's "ungrounded"
     bucket, never silently dropped).

4. **`lithrim_bench/harness/correction.py`** (NEW) — fine-tuning-ready correction record (RLVR north star).
   - `CorrectionRecord` schema, **append-only + versioned**:
     `{rollout: {judge_role, prompt-or-reason, output, confidence, model}, tool_call,
     tool_result, original_label, corrected_label, composite_before, composite_after,
     ontology_version, contract_version}`.
   - `emit(record) -> None` — appends to `out/ws0/corrections.ndjson` (lake-bound later
     via the etlp file→S3 connector; out of scope to wire that here).

5. **`lithrim_bench/harness/report.py`** (NEW) — composite report + calibration (report-only).
   - `composite(grounded) -> {score, verdict, reasoning, grounded_adjustments[]}`.
   - `calibration(result) -> {reliability_bins[], ece}` over the council confidences
     in the result. **REPORT-ONLY — not a gate** (the locked calibration gate is WS-4).

6. **`scripts/run_ws0.py`** (NEW) — the end-to-end runner.
   - Wires `ingest(case) → grade_replay → persist → ground → composite + calibration`,
     prints the composite verdict + the suppressed-finding correction + the calibration
     summary. `--case` defaults to `bench_scribe_v1_inject_condition_1bd0f10dc7b5`,
     `--live` opt-in (off by default).

7. **`tests/test_ws0.py`** (NEW) — offline tests against the captured baseline.
   - Covers A1–A4 below. **No network**; uses the baseline JSON + `out/scribe_v1.jsonl`
     as fixtures (per CLAUDE.md: tests run without network and without the Synthea CSV).
