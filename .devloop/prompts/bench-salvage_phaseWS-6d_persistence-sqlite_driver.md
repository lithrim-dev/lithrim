## Scope note (read first) — this is a WIRING job, not greenfield

WS-6d is the strangler-fig's **persistence half**: make the in-process pipeline's
provenance persistence **real** over SQLite so the product path carries **no Mongo
dependency**. The re-grep (2026-06-02) found **both halves already exist** — WS-6d
connects them:

- **The repository interface is already cut.** `runtime/pipeline/provenance.py` ships
  `class ProvenanceStore` (`:6`, `async save`) + `NoOpProvenanceStore` (`:11`) and
  literally aliases `MongoProvenanceStore = NoOpProvenanceStore` (`:16`) with the
  docstring *"M1 stub: no-op provenance (no Mongo). **Swap to a SQLite store later.**"*
  The orchestrator injects it (`orchestrator.py:201` param, `:217` default, single
  persist call `:361 await self._provenance_store.save(provenance, agent_id=…)`).
- **The SQLite backend already exists.** `harness/collections.py` (WS-1) is a
  **stdlib-sqlite3, zero-dependency** doc-shim: `DocShimCollection` (`:35`,
  `insert` idempotent-upsert / `get` / `find_by_fk`) + the 4 collections (`:105-110`).

**Two scope decisions are already MADE (monitor + user, 2026-06-02):**
1. **SQLite-only** this cycle — implement over the existing stdlib-sqlite3 doc-shim,
   zero new dependency; shape the impl so **PG/Aurora drops in later behind the same
   `ProvenanceStore` Protocol** (VPC tier; NOT this cycle).
2. **Grade-path only** — wire the store into the orchestrator's existing
   `save(provenance)` seam (the `report.composite` consumer). **NO** OBS `call_kpi`
   persistence (it has no persist site + no consumer; S-BS-36 — deferred).

The **frozen-contract rule** governs: persistence lives **behind** the `save` seam,
so `run_eval.run` / `report.composite` / the `PipelineResult` shape / the §10 BFF are
**untouched**. The grade record must be byte-identical with persistence on vs off.

## 2. Deliverables (file-by-file)

### D1, Implement `SqliteProvenanceStore`

1. **`lithrim_bench/runtime/pipeline/provenance.py`** — add `class SqliteProvenanceStore(ProvenanceStore)`:
   - `async save(self, provenance, *, agent_id=None)` — serialize the `PipelineProvenance` (`model_dump(mode="json")`) into a doc and **idempotent-upsert** it through the `harness/collections.py` doc-shim (the `PIPELINE_RUNS`/`COMPLIANCE_REPORT` collection per decision #4), keyed on `pipeline_run_id`. Keep it **fail-soft** (the call site is fire-and-forget; log, don't raise — mirror the current contract).
   - Extend the `ProvenanceStore` base with `async find_by_id(self, pipeline_run_id) -> Optional[dict]` (the read path, mirroring the backend Protocol `:30`); `NoOpProvenanceStore.find_by_id` returns `None`.
   - **Retire the `MongoProvenanceStore = NoOpProvenanceStore` alias** (`:16`) — the "Mongo" name is the thing this cycle deletes from the product path. Replace usages with an explicit default (decision #1/#3).
   - **No new dependency** — stdlib `sqlite3` via the existing doc-shim only.

### D2, Wire the store into the orchestrator default / harness

2. **`lithrim_bench/runtime/pipeline/orchestrator.py:217`** — repoint the default off the
   retired `MongoProvenanceStore` alias per **decision #1** (flip the default to
   `SqliteProvenanceStore`, or keep a `NoOpProvenanceStore` default and have the
   grade path/harness construct with `SqliteProvenanceStore`). `:201`/`:334`/`:361`
   otherwise **unchanged** — the `save` seam and the `PipelineProvenance` build stay
   put. Unit tests keep supplying their own (Null) store.
3. **`scripts/run_eval.py` / `lithrim_bench/harness/grade.py`** (only if decision #1 =
   opt-in) — the in-process grade path constructs the orchestrator **with** a
   `SqliteProvenanceStore`. `run_eval.run` **signature unchanged** (frozen contract);
   any new knob is keyword-defaulted and additive.

### D3, Read path + the eval-isolation invariant

4. **`provenance.py` (the store)** — `find_by_id(pipeline_run_id)` round-trips a saved
   provenance from SQLite (the §7 "route reads through `find_by_id`"). Preserve the
   **eval-isolation invariant**: re-running the same case (a new `pipeline_run_id` per
   `evaluate()`) writes a **distinct, non-colliding row**; persisting the same
   `pipeline_run_id` twice **upserts** (one row). The `kb_retrievals` 4-field summary
   persists as-is (no expansion — KB is WS-6d-KB).

### D4, Tests (offline, default-deps)

5. **`lithrim_bench/runtime/pipeline/tests/` (or `tests/`)** — offline, stdlib-sqlite,

   - `save` then `find_by_id` round-trips the provenance; idempotent upsert (same
     `pipeline_run_id` → 1 row); eval-isolation (two runs → 2 distinct rows).
   - **Frozen-contract diff:** the grade path returns the **same `PipelineResult` /
     grade record** with `SqliteProvenanceStore` vs a Null store (persistence is a
     pure side-effect; `report.composite` output identical).
   - default-deps clean: no new dependency (stdlib `sqlite3`); `import lithrim_bench` unaffected.

### D5, Session log
