## 0. Why this phase (the release-critical gap the A8 smoke exposed)

UAP-1/2/3 built the author→process machinery, but the UAP-3 `:5180` A8 smoke proved a
user **cannot author a judge in the shell**: `tool-judge_editor` is registered but not
mounted (chat + ⌘K inert) — **S-BS-62** — so the assignment had to go through `curl`. And
the one paid in_process run showed the authored per-judge audit comes back **all `None`**
(role/decision/model/reason/findings) — **S-BS-66** — so even a mounted editor's flip
wouldn't be *readable*. This phase closes both, plus a by-construction case that actually
flips on the **real** trio, so the product's core loop — *author a judge in the UI → run →
watch the verdict change → read the per-judge audit* — works end-to-end. This is the
release surface; the moat (UAP-3b) builds on top of it.

- **R10 author-assist (describe→card, the zyng `LLMClient`) is SPLIT OUT → UAP-5a-assist** (fast-follow). UAP-5a stays **deterministic + LLM-free + no licensing concern**.
- **Construct a real live-flip case IN this phase** (the full visceral paid finale), not just the $0 preview.
