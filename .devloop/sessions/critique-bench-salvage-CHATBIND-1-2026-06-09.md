## Findings
- **S-BS-106 (low, NEW — critic NB-2).** `_review_runs` fetches the newest 200 runs globally then Python-filters to `req_agent` (`app.py:1302-1303`). If the global history exceeds 200 rows AND the active agent's runs are all older than the newest 200 (a heavily-used shared collections DB), the active agent could show empty/short despite having runs. Acceptable for the current single-tenant/demo posture and well within the 500 cap; the proper fix is an **agent-filtered `list_all`** at the SQL level — which the spec explicitly keeps OUT of scope as a frozen-op change. Worth a follow-on if run volume grows. INFERRED.

Not a safety issue: `ChatRequest.agent` defaults to `DEFAULT_AGENT="ws0_default"` and `ToolContext.default_agent` defaults to `"ws0_default"`; `None` cannot occur (typed `str`); an explicit empty POST would resolve `get_agent("")` → a clean 404, not a crash.
